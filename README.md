O projeto **Leis de UX** reúne leis e efeitos de comportamento, princípios de design, heurísticas de usabilidade, Gestalt, modelos cognitivos e comportamentais, acessibilidade e métodos de pesquisa. Seu propósito é transformar conhecimento de UX em critérios práticos para criar produtos digitais melhores.

É desenvolvido e mantido pela **Planner** e publicado como projeto aberto para a comunidade.

> Não é uma lista de regras para justificar preferências visuais. É uma metodologia para compreender tarefas, diagnosticar fricções, tomar decisões fundamentadas e validar resultados.

## Por que este projeto existe

Hoje, pessoas e equipes criam sites, dashboards, plataformas e aplicações com ferramentas de IA. A velocidade de implementação aumentou, mas gerar uma interface não garante que ela seja compreensível, acessível ou fácil de usar.

O projeto ajuda designers, desenvolvedores, founders, equipes de produto e agentes de IA a aplicar fundamentos de experiência do usuário durante a concepção, implementação e avaliação de produtos digitais.

## O que você encontra aqui

- **Base de conhecimento:** leis, efeitos, princípios, heurísticas, modelos e glossário.
- **Método de aplicação:** análise estruturada por O Quê, Por Quê, Para Quem, Onde, Quando e Como.

- **Integrações com IA:** instruções para usar a metodologia em agentes de desenvolvimento e ferramentas de criação.
- **Exemplos e demonstrações:** materiais para aplicar e ensinar os conceitos.

## Como a metodologia funciona

Cada conceito deve ser aplicado considerando seis dimensões:

| Dimensão | Pergunta |
|---|---|
| **O Quê** | O que o conceito descreve? |
| **Por Quê** | Qual mecanismo ou problema ajuda a explicar? |
| **Para Quem** | Quais pessoas e contextos são afetados? |
| **Onde** | Em quais telas, componentes ou etapas se aplica? |
| **Quando** | Quais condições tornam sua aplicação pertinente? |
| **Como** | Que decisão prática pode ser implementada e validada? |

A metodologia também exige separar evidências observadas, dados, inspeção especializada e hipóteses. Leis e efeitos descrevem tendências, não resultados garantidos.

## Compatibilidade com ferramentas de IA

O conteúdo é escrito em Markdown e pode ser consultado por diferentes modelos e ferramentas. A execução como Agent Skill depende do suporte e do mecanismo de instalação de cada ambiente.

- **Claude Code, Codex e ferramentas compatíveis com Agent Skills:** consulte a skill e as instruções de instalação.
- **Lovable:** use os arquivos como contexto do projeto ou referência nas instruções do agente. O guia inclui um fluxo específico para auditoria e implementação cuidadosa.
- **Cursor e GitHub Copilot:** disponibilize a documentação como contexto ou configure-a conforme os mecanismos suportados pela versão utilizada.
- **ChatGPT e Gemini:** forneça os arquivos como contexto ou utilize ambientes de desenvolvimento compatíveis. A disponibilidade varia entre interfaces, APIs e ferramentas de linha de comando.

Veja a [matriz de compatibilidade](docs/compatibilidade-e-integracoes.md). Não presumimos suporte nativo quando a plataforma oferece apenas uso contextual.

## Idioma e escopo

A documentação inicial está em **português brasileiro (pt-BR)**. Termos originais em inglês são apresentados quando ajudam a identificar conceitos e fontes.

O campo de UX não possui uma lista universal e fechada de leis. Esta obra diferencia leis, efeitos, princípios, heurísticas, modelos e princípios de engenharia. Não atribui precisão científica indevida a conceitos populares.
